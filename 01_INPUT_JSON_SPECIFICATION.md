# Спецификация входного JSON счёта

- **Файл:** `sample-data/invoice_demo.json`
- **Версия спецификации:** 0.1
- **Статус:** предварительная спецификация учебного входного формата
- **Язык документа:** русский

## 1. Назначение

Документ описывает структуру JSON, который принимает учебный проект `e-rechnung-python`.

Текущая структура основана на демонстрационном файле `sample-data/invoice_demo.json` в репозитории. Она нужна для согласованной разработки проверок, расчётов и последующего преобразования данных в XRechnung XML.

**Важно:** эта спецификация описывает внутренний формат входных данных проекта. Она не является полной схемой XRechnung, не подтверждает соответствие EN 16931 и не означает, что все перечисленные поля обязательны по немецкому законодательству.

## 2. Общая структура

Корневой JSON-объект представляет один счёт и содержит:

| Поле | JSON-тип | Назначение |
|---|---|---|
| `invoice_number` | string | Номер счёта |
| `issue_date` | string | Дата выставления счёта |
| `currency` | string | Валюта счёта |
| `buyer_reference` | string | Ссылка/идентификатор, предоставленный покупателем |
| `seller` | object | Данные продавца |
| `buyer` | object | Данные покупателя |
| `items` | array of object | Позиции счёта |

Пример верхнего уровня:

```json
{
  "invoice_number": "DEMO-2026-001",
  "issue_date": "2026-10-08",
  "currency": "EUR",
  "buyer_reference": "DEMO-B2B-01",
  "seller": {},
  "buyer": {},
  "items": []
}
```

## 3. Описание полей счёта

| Поле | Тип JSON | Пример | Значение и комментарий |
|---|---|---|---|
| `invoice_number` | string | `"DEMO-2026-001"` | Уникальный идентификатор/номер счёта в системе продавца. Правила нумерации и допустимые символы определяются отдельной проверкой. |
| `issue_date` | string | `"2026-10-08"` | Дата выставления счёта. В текущем формате используется календарная дата `YYYY-MM-DD`. |
| `currency` | string | `"EUR"` | Код валюты счёта. В текущем учебном сценарии поддерживается только EUR. |
| `buyer_reference` | string | `"DEMO-B2B-01"` | Ссылка покупателя (например, номер заказа или внутренний референс). Точное соответствие бизнес-элементу XRechnung ещё требуется подтвердить. |

## 4. Объект `seller` — продавец

` seller ` содержит идентификационные, адресные и контактные данные продавца.

| Поле | Тип JSON | Пример | Значение и комментарий |
|---|---|---|---|
| `name` | string | `"Beispiel Lieferant GmbH"` | Наименование продавца. |
| `street` | string | `"Beispielstraße 1"` | Улица и номер дома одной строкой. |
| `postal_code` | string | `"10115"` | Почтовый индекс. Строка, а не число: индекс может содержать ведущие нули и буквенные символы. |
| `city` | string | `"Berlin"` | Населённый пункт/город. |
| `country_code` | string | `"DE"` | Код страны. В примере используется двухбуквенный код `DE`; допустимый перечень кодов будет определён отдельно. |
| `vat_id` | string | `"DE000000000"` | Идентификатор плательщика НДС продавца (USt-IdNr. в немецком контексте). Пример фиктивный и не предназначен для реального использования. |
| `email` | string | `"demo-seller@example.invalid"` | Адрес электронной почты продавца. |

## 5. Объект `buyer` — покупатель

`buyer` содержит идентификационные, адресные и контактные данные покупателя.

| Поле | Тип JSON | Пример | Значение и комментарий |
|---|---|---|---|
| `name` | string | `"Musterkunde GmbH"` | Наименование покупателя. |
| `street` | string | `"Musterweg 2"` | Улица и номер дома одной строкой. |
| `postal_code` | string | `"20095"` | Почтовый индекс. Строка, а не число. |
| `city` | string | `"Hamburg"` | Населённый пункт/город. |
| `country_code` | string | `"DE"` | Код страны. В примере используется `DE`. |
| `email` | string | `"demo-buyer@example.invalid"` | Адрес электронной почты покупателя. |

В демонстрационном JSON у покупателя нет поля `vat_id`. Это отражает только текущий пример и **не является утверждением**, что идентификатор покупателя никогда не понадобится.

## 6. Массив `items` — позиции счёта

`items` — массив объектов. Каждый объект описывает одну позицию счёта: товар или услугу.

В демонстрационном JSON каждая позиция содержит следующие поля:

| Поле | Тип JSON | Пример | Значение и комментарий |
|---|---|---|---|
| `description` | string | `"Demo-Arbeitsleistung"` | Текстовое описание товара или услуги. |
| `quantity` | string | `"2"` | Количество товара или объём услуги. Передаётся строкой, чтобы преобразовать значение непосредственно в `decimal.Decimal`, не используя двоичный `float`. Должно быть положительным и конечным согласно текущему учебному правилу проверки. |
| `unit_code` | string | `"HUR"` | Код единицы измерения количества. В примере `HUR` используется для часа, `C62` — для единицы. Точный допустимый список кодов и источник классификатора должны быть зафиксированы отдельно. |
| `net_unit_price` | string | `"50.00"` | Цена **одной единицы** товара или услуги без НДС. Например, `quantity = "2"` и `net_unit_price = "50.00"` дают сумму позиции без НДС `100.00` до применения правил округления. Передаётся строкой для преобразования в `decimal.Decimal`. |
| `vat_percent` | string | `"19"` | Ставка НДС в процентах. Например, `"19"` означает 19 %. Это именно процентная ставка, а не коэффициент `0.19`. Допустимые значения и налоговые категории будут определены отдельной задачей. |

### 6.1. Пример расчёта позиции

Для данных:

```json
{
  "quantity": "2",
  "unit_code": "HUR",
  "net_unit_price": "50.00",
  "vat_percent": "19"
}
```

Расчёт до округления:

- количество: 2 часа;
- цена за один час без НДС: 50,00 EUR;
- сумма позиции без НДС: `2 × 50.00 = 100.00 EUR`;
- НДС при ставке 19 %: `100.00 × 19 / 100 = 19.00 EUR`;
- сумма с НДС: `119.00 EUR`.

Это иллюстрация арифметики, а не полная политика расчёта и округления XRechnung. Правила точности и округления должны быть определены отдельно и подтверждены тестами.

## 7. Представление чисел в JSON

Для количества, цены и ставки НДС в текущем формате используются JSON-строки:

```json
{
  "quantity": "2",
  "net_unit_price": "50.00",
  "vat_percent": "19"
}
```

Причина: значения можно передать в `decimal.Decimal` напрямую из строк. Не следует сначала преобразовывать их в `float`, поскольку `float` использует двоичное представление и может вносить погрешность в десятичные значения.

В Python ожидаемое преобразование выглядит концептуально так:

```python
from decimal import Decimal

quantity = Decimal("2")
net_unit_price = Decimal("50.00")
vat_percent = Decimal("19")
```

## 8. Что пока не определено

Следующие решения нельзя считать принятыми только на основании демонстрационного JSON:

1. Обязательность каждого поля и поведение при его отсутствии.
2. Допустимость `null` и пустых строк.
3. Дополнительные поля продавца и покупателя (например, идентификаторы, контактные данные, дополнительные строки адреса).
4. Полный перечень допустимых кодов `unit_code`.
5. Допустимые ставки и налоговые категории, включая освобождения и специальные случаи.
6. Допустимый формат десятичных строк: например, разрешены ли экспоненциальная запись, разделители или подчёркивания.
7. Максимальная точность количества, цены и ставки.
8. Политика округления сумм.
9. Точное соответствие каждого поля бизнес-элементам (BT) EN 16931 и синтаксису UBL 2.1.
10. Поддержка кредит-нот, скидок, дополнительных сборов и нескольких налоговых категорий.

Эти пункты следует уточнять по мере появления соответствующих требований и задач. Не следует вводить ограничения без основания в согласованном контракте или применимом стандарте.

## 9. Связь с кодом и тестами

При изменении структуры входного JSON необходимо согласованно обновить:

1. этот документ;
2. `sample-data/invoice_demo.json`;
3. соответствующие проверки в `src/e_rechnung/domain/`;
4. тесты в `tests/`.

Учебные задания могут объяснять отдельные поля и проверки, но этот файл остаётся единым местом для описания структуры и назначения полей.

## 10. Источники и границы применимости

- Демонстрационная структура: [`sample-data/invoice_demo.json`](../sample-data/invoice_demo.json).
- Официальный текст § 14 UStG: <https://www.gesetze-im-internet.de/ustg_1980/__14.html>.
- Официальная страница KoSIT/XRechnung: <https://xeinkauf.de/xrechnung/>.

Закон и спецификация XRechnung определяют требования к электронному счёту. Данный документ фиксирует только текущий внутренний JSON-контракт проекта. Соответствие каждого поля нормативным бизнес-элементам должно подтверждаться отдельно.
